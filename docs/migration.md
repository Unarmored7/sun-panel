# 首次迁移演练与限制

本文保留 2026-10-10 首次从官方闭源镜像切换到本 fork 前的演练背景。当时线上版本比开源源码更新，不能把旧版容器直接挂在生产数据上，因此先读取数据结构，再补兼容字段，仅在独立副本上启动和验证。切换已完成，后续部署约定见 [production.md](production.md)；以下检查仍适用于新的迁移演练。

必须检查：

1. 数据库副本中的分组、卡片数量与 ID、标题、URL、图标、排序保持一致。
2. 私密分组只对所属用户可见；访客按 ID 请求私密分组同样被拒绝。
3. 分组的详情/图标样式、全局样式继承、清空覆盖值可正常保存。
4. 前端构建与类型检查、Go 测试、容器构建通过。
5. 数据副本内不保留生产账号密码、登录令牌或 SMTP 设置；实例仅绑定本机地址。
6. 设计系统的三种视口、短/长内容页布局检查通过。

已知边界：

- 基线是 v1.3.0，本次兼容现有导航链接数据；后续官方卡片类型与插件尚未实现。
- 登录密码仍使用上游旧版哈希格式以维持兼容，升级密码存储和会话机制应作为下一阶段任务。
- 演练不覆盖生产的 `index.html` 或数据库；首次切换前一直保持原容器运行。
- 正式切换应先停止写入、建立完整备份，再用新建副本部署；回滚使用旧镜像和未被旧源码改写的备份。

首次迁移时的依赖审计记录：已移除旧 SVG 插件及其过时构建链。当时 pnpm 审计剩余一个未发布修复的 `braces` 高危告警，来自 Tailwind 3 的构建依赖，不进入运行镜像。此记录不是最新依赖审计结果；后续维护和升级 Tailwind 时应重新检查，不能据此认为整个旧版应用已经完成安全审计。
