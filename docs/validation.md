## URL 维护与加载优化（2026-10-10）

- 前端类型检查和构建通过，ESLint 0 错误、24 条原有警告；64 份压缩 JS 解压后与对应构建文件逐字节一致。
- 后端完整 `go test ./...` 通过；新增 13 项测试覆盖批量可见性、规范化 URL 更新、旧重复记录、并发创建、软删除后重加、共享缓存和上传文件回收、延迟下载完成时的删除、图标优先级、下载边界及 HTTP 压缩/缓存头。
- 浏览器 12 个布局场景、6 种分类栏宽度、搜索与键盘操作、登录与私密分组、深浅主题均通过，无运行时错误。开发副本仍为 14 个分组、215 张卡片，公开 162 张。
- 真实网站通过“只输入 URL”创建书签，图标缓存在服务器；重复保存复用 ID，最新名称生效。模拟迟到的识别响应不会覆盖新 URL，手动名称得到保留，测试数据已删除。
- 在 150ms 附加延迟、1.6Mbps 下载、CPU 4 倍减速的 Chrome 实验条件下，旧生产版桌面冷加载 LCP 11.08s、全部书签 12.77s；新开发容器分别为 3.99s、3.96s。首屏脚本传输 1.57MB → 258KB，API 15 → 4 次；桌面 CLS 0.176 → 0.0006，移动端 0.219 → 0.0025。两次环境不同，正式站点同地址测量结果保存在部署后的工作区报告中；这些是实验数据，不是实际访客的统计。
